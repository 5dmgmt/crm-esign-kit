# crm-esign-kit

自社の Vercel と Supabase に入れて使う、顧客台帳と電子契約のキットです。連絡先・メモ・やりとり・資料と、契約書の作成から署名・締結記録までを、一つの管理画面で扱えます。連絡先や契約書などのデータは、自社で作った Supabase のプロジェクトに保存されます（メールを送る設定にした場合、メールは選んだ送信サービスを通ります）。

公開リポジトリ: https://github.com/5dmgmt/crm-esign-kit

Claude Code に手伝ってもらいながら入れる場合は、[PROMPT.md](PROMPT.md) の枠をそのまま貼り付けてください。README に沿って、設定から自分宛てのテスト契約までを一緒に進めます。

## できること

### 顧客台帳

- **連絡先**: 姓・名・会社名・役職・メール・電話・郵便番号・住所・タグ・段階・状態（利用中／アーカイブ）を登録します。氏名・会社・メール・タグで検索し、段階・状態・タグで絞り込み、最終接点か更新日時の新しい順に並べます。メールは連絡先ごとに一つです。同じメールで登録しようとすると、すでに登録があることをお知らせします。
- **カルテ**: 連絡先ごとの画面に、プロフィール・メモとフォロー・やりとり・資料・電子契約をまとめて表示します。
- **メモとフォロー**: メモ・面談メモ・フォロー（期日つき）を残します。フォローは完了にしたり、未完了に戻したりできます。
- **やりとり**: 面談・電話・メール・メモを、日時・件名・内容（面談は議事録）つきで時系列に残します。記録すると、その連絡先の最終接点が更新されます。
- **資料**: URL か、ファイル（Supabase Storage の非公開の置き場）で登録し、版を付け、やりとりに紐付けます。ファイルを開くリンクは 10 分間有効です。
- **CSV の取り込み・書き出し**: UTF-8 の CSV（BOM 付きも可）を取り込みます。見出しは自動で対応づけ、手で直すこともできます。確定の前に、メールの重複と入力の不備を一覧で確かめられます。書き出しは Excel でそのまま開ける BOM 付きの UTF-8 です。
- **今日の予定**: 日本時間の今日の面談、期日が今日までの未完了のフォロー、最近更新した連絡先を、管理画面の最初のページに出します。
- **段階**: 「見込み・提案中・契約・取引中・休眠」（初期値）のように、`kit.config.ts` で決めた段階で連絡先を管理します。契約が締結されると、連絡先の段階をひな形で決めた段階へ進め、やりとりに「契約を締結（文書番号 …）」と記録します。
- **整理**: ふだんはアーカイブを使います。完全に削除するときは、連絡先の氏名を入力して確かめます。どちらの場合も、契約書の記録はそのまま残ります。

### 電子契約

- **作成**: ひな形を選び、項目を入れて契約書を作ります。カルテの「この連絡先の契約を作る」から始めると、会社名・氏名・住所・メールが最初から入ります。作成した時点で本文を固定し、7 桁の文書番号を振ります。
- **送付**: 作成と同時に署名依頼メールを送れます。作成後の画面には署名用リンクも出るので、メールを使わない場合はそのリンクを相手に渡せます。
- **署名**: 相手は署名用リンクを開いて全文を確かめ、会社名（法人の場合）と氏名を入れ、同意のチェックを付けて署名します。相手のログインは要りません。署名用リンクの有効期限は、初期値で 14 日です。
- **締結記録**: 署名した日時、署名者の会社名と氏名、IP アドレス、ブラウザの情報（User-Agent）を記録します。発行者の側は、契約書を作成した日時と発行者名を「発行者の署名記録」として残します。メールを送る設定のときは、締結すると、相手と発行者の両方へ締結記録のメールを送ります。
- **本文ハッシュの照合**: 作成時に本文の SHA-256 を保存し、署名ページ・管理画面・署名の受け付けのたびに照らし合わせます。一致しないときは署名を受け付けず、「ハッシュ不一致」と表示します。
- **無効化**: 署名前の契約書は、理由を記録して無効にできます。無効にした契約書の署名用リンクを開くと「この契約書は無効です」と表示され、署名も閲覧もできなくなります。
- **印影**: `kit.config.ts` に書いた文字（空白を除いて 8 文字まで）と色から、発行者の丸い印影を画像で作り、契約書に入れます。
- **控えの印刷**: 締結後のページの「控えを印刷・PDF保存」から、ブラウザの印刷機能で紙か PDF に残せます。
- **ひな形をファイルで追加**: `templates/contracts/` にフォルダを足すと、作成画面のひな形が増えます（[ひな形の足し方](#ひな形の足し方)）。

画面とメールの日時は、日本時間で表示します。

## v1 に入っていないこと（v2 で予定しているもの）

- Gmail・Google カレンダーとの同期（v1 では、やりとりと面談を画面から記録します）
- 名刺の読み取り
- 一斉配信（v1 のメールは、署名依頼と締結記録の通知です）
- 英語の画面と文面（v1 は日本語です）
- 複数の会社の同居（v1 は、一つの導入で一つの会社を扱います。発行者は `kit.config.ts` に書いた一社です）

## 電子契約の位置づけ

- このキットの電子契約は、契約書の全文を確かめた相手が、氏名を入力して同意したことを、日時と本文のハッシュとともに記録する仕組みです。
- 認証局が発行する電子証明書を使う電子署名（電子署名法が定める推定の効力が及ぶことを前提にした形）とは、別の仕組みです。どの契約にこの形が合うかは、契約の内容や相手との関係に合わせてご判断ください。迷うときは、弁護士などの専門家にご相談ください。
- 署名できるのは、署名用リンクを開いた人です。リンクは相手のメールアドレスへ直接届け、共有の場所には貼らないようにしてください。
- 同梱のひな形 `templates/contracts/sample-gyomu-itaku/` は、差し込みの書き方を示す見本で、法律相談ではありません。実際に使う契約書の文面は、自社で用意したもの（必要に応じて専門家に確かめたもの）に置き換えてお使いください。

## 必要なもの

- **Node.js 24 以上**と npm
- **Git と GitHub のアカウント**（自社用の非公開リポジトリを置き、Vercel につなぎます）
- **Supabase のアカウント**: 無料枠で始められます。無料枠の条件と料金は [Supabase の料金ページ](https://supabase.com/pricing)をご覧ください。無料枠のプロジェクトは、しばらく使わないと一時停止されることがあります。
- **Vercel のアカウント**: Hobby プランは個人の非商用の利用に限られます（[Hobby プランの条件](https://vercel.com/docs/plans/hobby)）。事業で使う場合は、Pro などの有料プランを選びます（[Vercel の料金ページ](https://vercel.com/pricing)）。
- **Google Cloud の OAuth クライアント**: 管理者が Google アカウントでログインするために使います（[Google Cloud コンソール](https://console.cloud.google.com/)）。
- **メールの送り方**（どれか一つ）
  - SMTP（自社のメールサーバーなど）
  - Resend（[Resend の料金ページ](https://resend.com/pricing)）
  - メールなし（`none`）: 作成後の画面に出る署名用リンクを、自分のメールなどで相手に送ります。締結記録のメールは送られないので、相手には締結後のページ（同じリンク）から控えを印刷してもらいます。

## 入れ方

### 1. clone して依存を入れる

```bash
git clone https://github.com/5dmgmt/crm-esign-kit.git
cd crm-esign-kit
npm ci
```

### 2. Supabase のプロジェクトを作る

1. Supabase で新しいプロジェクトを作ります。地域（Region）は、自社とお客様に近い場所（たとえば東京）を選べます。データベースのパスワードは、ご自身で控えておきます。
2. プロジェクトの設定画面から、次の 2 つを確かめます。値はこのあと環境変数に入れます。
   - Project URL → `NEXT_PUBLIC_SUPABASE_URL`
   - API Keys にあるサーバー用の秘密のキー（`service_role`）→ `SUPABASE_SERVICE_ROLE_KEY`。このキーはすべてのデータを読み書きできるため、サーバーの環境変数にだけ置きます。

### 3. migrations を番号順に適用する

`supabase/migrations/` の SQL を、番号の小さい順に一度ずつ実行します。

| ファイル | 作るもの |
| --- | --- |
| `0001_init.sql` | 連絡先・メモ・やりとり・資料・資料の紐付け・電子契約・設定のテーブル。全テーブルの RLS（サーバー用のキーだけに許可）。資料用の非公開の置き場 `crm-documents` |
| `0002_crm_follow_documents.sql` | フォローの期日と完了日時、資料のファイル名・種類・大きさの列、今日の予定のための索引 |

**SQL エディタで適用する場合**: Supabase の画面の SQL Editor に、`0001_init.sql` の中身を貼って実行し、続けて `0002_crm_follow_documents.sql` を同じように実行します。

**supabase CLI で適用する場合**:

```bash
supabase link --project-ref <プロジェクトの ID>
supabase db push
```

途中でデータベースのパスワードを聞かれたら、ご自身で入力します。CLI の使い方は [Supabase CLI のドキュメント](https://supabase.com/docs/guides/cli)をご覧ください。

`0001_init.sql` は、新しいプロジェクトに一度だけ実行します。二度目はテーブルがすでにあるため、エラーで止まります。途中で止まったときは、Table Editor でどこまで入ったかを確かめてから進めます。

### 4. Google の OAuth クライアントを作る

1. Google Cloud コンソールでプロジェクトを作り（既存のものでも使えます）、Google Auth Platform（OAuth 同意画面）でアプリ名とサポート用のメールを設定します。
2. 「クライアント」から OAuth クライアント ID を作ります。アプリケーションの種類は「ウェブ アプリケーション」です。
3. 「承認済みのリダイレクト URI」に、次を登録します。`<SITE_URL>` は本番の URL（例: `https://crm.example.com`）です。
   - `<SITE_URL>/api/auth/callback/google`
   - ローカルで試す場合は、あわせて `http://localhost:3000/api/auth/callback/google`
4. 表示されたクライアント ID とクライアント シークレットを、`GOOGLE_CLIENT_ID` と `GOOGLE_CLIENT_SECRET` に使います。

リダイレクト URI は、環境変数 `NEXTAUTH_URL` に `/api/auth/callback/google` を足した形になります。`NEXTAUTH_URL` と `SITE_URL` は同じ値にそろえてください。

同意画面の公開ステータスが「テスト」のあいだは、テストユーザーに登録した Google アカウントだけがログインできます。管理者のアカウントをテストユーザーに入れるか、自社の Google Workspace の中だけで使う場合は対象を「内部」にします。

### 5. kit.config.ts を書く

```bash
cp kit.config.example.ts kit.config.ts
```

`kit.config.ts` を開き、発行者（自社）の情報などを書きます。

| 項目 | 内容 |
| --- | --- |
| `issuer.companyName` | 発行者の名前。契約書・メール・発行者の署名記録に入ります |
| `issuer.representativeTitle` | 代表者の肩書き（例: 代表取締役） |
| `issuer.representativeName` | 代表者の氏名 |
| `issuer.addressLines` | 住所を 2 行で書きます（`["1 行目", "2 行目"]`） |
| `issuer.contactEmail` | 問い合わせ先のメール。メールの末尾に入り、締結記録の通知もここへ届きます。差出人のアドレスを別に決めていないときは、差出人にもなります |
| `issuer.phone` | 電話番号（空でも使えます） |
| `issuer.sealText` | 印影の文字。空白を除いた先頭 8 文字までを使います |
| `issuer.sealColor` | 印影の色。`#` と 16 進数 6 桁で書きます（例: `#b8322a`） |
| `siteUrl` | 本番の URL。環境変数 `SITE_URL` があれば、そちらを使います |
| `mail.transport` | `smtp`・`resend`・`none` のどれか。環境変数 `MAIL_TRANSPORT` があれば、そちらを使います |
| `mail.fromName` | メールの差出人の表示名 |
| `signingTokenDays` | 署名用リンクの有効日数（初期値 14） |
| `signedDocumentViewDays` | 締結後に同じリンクで契約書を開ける日数。締結日時から数えます。`null` で期限なし（初期値） |
| `stageTags` | 連絡先の段階の一覧。並びの最初が、新しい連絡先と、CSV で段階が空の行の初期値になります |
| `autoAdvanceStageOnSign` | 締結したとき、連絡先の段階をひな形の `stageTagOnSign` へ進めるか（初期値 `true`） |

- 見本のひな形は、締結すると段階を「契約」へ進めます。`stageTags` から「契約」を外すときは、ひな形の `stageTagOnSign` も合わせて直します。
- `stageTags` の名前を変えたり外したりすると、その段階の連絡先は、次に保存するときに段階を選び直します。
- `kit.config.ts` がないまま起動すると、画面の上に「設定がまだです」と出て、見本の値で動きます。`kit.config.ts` を作ったあとは、`npm run dev` を起動し直します。
- `kit.config.ts` は `.gitignore` に入っています。公開リポジトリに会社の情報を載せないためです。Vercel にデプロイするときの扱いは、[手順 8](#8-vercel-にデプロイする) で説明します。

### 6. 環境変数を入れる

名前は `.env.example` にそろっています。

| 名前 | 入れるもの |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase の Project URL。サーバーの中でだけ使います |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase のサーバー用の秘密のキー（秘密） |
| `NEXTAUTH_URL` | ログインの戻り先の基準になる URL。`SITE_URL` と同じ値です |
| `NEXTAUTH_SECRET` | ログインの状態を守るための長いランダムな文字列（秘密）。`openssl rand -base64 32` などで作ります |
| `GOOGLE_CLIENT_ID` | Google の OAuth クライアント ID |
| `GOOGLE_CLIENT_SECRET` | Google の OAuth クライアント シークレット（秘密） |
| `ADMIN_EMAILS` | 管理画面に入れる Google アカウントのメール。複数のときはカンマで区切ります（例: `owner@example.com,staff@example.com`）。大文字と小文字は同じものとして扱います |
| `SITE_URL` | 本番の URL（例: `https://crm.example.com`）。署名用リンクの組み立てと、書き込み操作の送り元の確認に使います |
| `MAIL_TRANSPORT` | `smtp`・`resend`・`none` のどれか。空のときは `kit.config.ts` の `mail.transport` を使います |
| `SMTP_HOST` | SMTP サーバーの名前 |
| `SMTP_PORT` | SMTP のポート。空のときは 587。465 のときは暗号化した接続で送ります |
| `SMTP_USER` | SMTP のユーザー名 |
| `SMTP_PASS` | SMTP のパスワード（秘密） |
| `SMTP_FROM` | SMTP の差出人アドレス。空のときは `MAIL_FROM`、それも空なら `issuer.contactEmail` |
| `RESEND_API_KEY` | Resend の API キー（秘密） |
| `MAIL_FROM` | 差出人アドレス。Resend では、Resend で認証したドメインのアドレスにします。空のときは `issuer.contactEmail` |

使わないメールの方式の欄は、空のままで構いません。

- **ローカル**: `.env.example` を `.env.local` に写し、ご自身のエディタで値を入れます。`.env.local` は `.gitignore` で除外されています。ローカルでは `SITE_URL` と `NEXTAUTH_URL` を `http://localhost:3000` にします。
- **Vercel**: プロジェクトの Settings → Environment Variables の画面か、`vercel env add <名前> production` で Production に入れます。秘密の値は sensitive にします（CLI では `--sensitive` を付けます）。環境変数を変えたあとは、デプロイし直すと反映されます。
- 秘密の値は、チャットやファイル、コミットに書かずに扱ってください。
- 管理画面は、`SITE_URL` と同じ URL で開いて使います。別の URL（Vercel が自動で付ける `*.vercel.app` やプレビューの URL など）で開くと、保存などの書き込み操作が「この操作は管理画面から行ってください」で止まります。

### 7. ローカルで確かめる

```bash
npm test
npm run typecheck
npm run dev
```

`http://localhost:3000/login` を開き、`ADMIN_EMAILS` に入れた Google アカウントでログインします。「今日の予定」が開き、「連絡先」で一件登録できれば、Supabase との接続とログインは整っています。

### 8. Vercel にデプロイする

1. GitHub で、空の**非公開**リポジトリを新しく作ります。`kit.config.ts` に自社の情報が入るため、Fork ではなく新しいリポジトリを使います。
2. clone したフォルダで、送り先を付け替えて push します。`kit.config.ts` は `.gitignore` に入っているため、`-f` を付けて加えます。

   ```bash
   git remote rename origin upstream
   git remote add origin https://github.com/<あなたのアカウント>/<リポジトリ名>.git
   git add -f kit.config.ts
   git commit -m "chore: 自社の設定を追加"
   git push -u origin main
   ```

   `upstream` は公開リポジトリで、新しい版の取り込みに使います。`kit.config.ts` は、自社の非公開リポジトリにだけ置きます。

3. Vercel の Add New → Project から、そのリポジトリを読み込みます。Framework は Next.js が自動で選ばれます。プロジェクト設定の Node.js の版が 24 以上になっているかを確かめます。
4. [手順 6](#6-環境変数を入れる) の環境変数を Production に入れ、デプロイします。
5. 独自ドメインを使う場合は、Vercel の Domains で設定し、`SITE_URL`・`NEXTAUTH_URL`・Google のリダイレクト URI を、その URL にそろえます。

### 9. 自分宛てのテスト契約で一巡する

1. 本番の管理画面にログインし、「連絡先」で自分を連絡先として登録します（メールは自分のもの）。
2. カルテの「この連絡先の契約を作る」から、見本のひな形で契約書を作ります。題名に「テスト」と入れておくと、あとで見分けやすくなります。「作成後に署名依頼メールを送る」に印を付けて作成します。
3. 届いたメール（メールなしの設定なら、画面に出た署名用リンク）から署名ページを開き、全文を確かめて署名します。ログインしていないブラウザ（シークレットウィンドウなど）で開くと、相手からの見え方を確かめられます。
4. 締結後のページで、「ハッシュ照合: 一致」と締結記録を確かめ、「控えを印刷・PDF保存」を試します。
5. 締結記録のメールが自分と `issuer.contactEmail` に届いたこと、管理画面の「契約書」で状態が「締結済み」になったこと、連絡先の段階が「契約」へ進み、やりとりに締結の記録が入ったことを確かめます。
6. 無効化も試す場合は、もう一通作り、署名する前に契約書の画面の「契約書を無効にする」から理由を入れて無効にし、署名用リンクを開くと「この契約書は無効です」と出ることを確かめます。

テストで作った契約書も、記録として管理画面に残ります。

## ひな形の足し方

ひな形は、フォルダ一つにファイル二つです。見本の `sample-gyomu-itaku` を写して始めると、書き方を確かめながら進められます。

```text
templates/contracts/<id>/
  schema.json     入力項目の定義
  template.html   契約書の本文（差し込みの印つき）
```

`<id>` は、英小文字・数字・ハイフンで 64 文字まで（先頭は英小文字か数字）です。`schema.json` の `id` と同じ名前にします。

### schema.json

```json
{
  "id": "hoshu-keiyaku",
  "name": "保守契約",
  "version": "1.0.0",
  "allowIndividual": false,
  "stageTagOnSign": "契約",
  "fields": [
    { "key": "title", "label": "契約書名", "type": "text", "required": true, "max": 120, "defaultValue": "保守契約書" },
    { "key": "clientCompany", "label": "お客様の会社名", "type": "text", "required": true, "requiredFor": "corporation", "max": 120 },
    { "key": "clientName", "label": "お客様の氏名", "type": "text", "required": true, "max": 60 },
    { "key": "startDate", "label": "開始日", "type": "date", "required": true, "max": 10 },
    { "key": "monthlyFee", "label": "月額（円）", "type": "money", "required": true, "max": 12 },
    { "key": "scope", "label": "保守の範囲", "type": "list", "required": true, "max": 10 }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| `id` | フォルダ名と同じ名前 |
| `name` | 作成画面のひな形の一覧に出る名前 |
| `version` | ひな形の版。契約書ごとに記録されます。文面を変えたら上げます |
| `allowIndividual` | 個人のお客様にも使うなら `true`、法人だけなら `false` |
| `stageTagOnSign` | 締結したときに連絡先を進める段階。`kit.config.ts` の `stageTags` にある名前か、進めないなら `null` |
| `fields` | 入力項目の一覧 |

`fields` の一つずつには、次を書きます。

| 項目 | 内容 |
| --- | --- |
| `key` | 差し込みの名前。英字で始め、英数字と `_`・`.`・`-` を使えます |
| `label` | 作成画面に出る名前 |
| `type` | `text`（1 行）・`textarea`（複数行）・`date`（`YYYY-MM-DD`）・`money`（数字。小数は 2 桁まで）・`list`（1 行に 1 項目の箇条書き） |
| `required` | 必須なら `true` |
| `requiredFor` | `corporation` か `individual`（任意）。その区分のときだけ必須にし、作成画面でもその区分のときだけ表示します |
| `max` | 文字数の上限。`list` では項目数の上限です（各項目は 500 文字まで） |
| `defaultValue` | 最初から入れておく値（任意） |

次の `key` は、キットの中で決まった使い方をします。

- `clientName`: お客様の氏名。契約書の相手として記録し、メールの宛名にも使います。どのひな形にも入れます。
- `clientCompany`: 法人のときの会社名。記録・メールの宛名・署名欄の初期値に使います。
- `title`: 契約書名。一覧とメールの件名に使います。ないときは `name` を使います。
- `clientAddress`: カルテから作るとき、連絡先の郵便番号と住所が最初から入ります。

### template.html

| 書き方 | 入るもの |
| --- | --- |
| `{{key}}` | 項目の値。HTML として安全な形に直して入れます |
| `{{#each key}}…{{this}}…{{/each}}` | `list` の項目を一つずつ繰り返します |
| `{{#corporation}}…{{/corporation}}` | 法人のときだけ出す部分 |
| `{{#individual}}…{{/individual}}` | 個人のときだけ出す部分 |
| `{{issuer.companyName}}`・`{{issuer.representativeTitle}}`・`{{issuer.representativeName}}` | 発行者の名前、代表者の肩書きと氏名 |
| `{{issuer.addressLine1}}`・`{{issuer.addressLine2}}` | 発行者の住所の 1 行目と 2 行目 |
| `{{issuer.contactEmail}}`・`{{issuer.phone}}` | 発行者の問い合わせ先 |
| `{{issuer.seal}}` | 発行者の印影の画像 |

```html
<div class="esign-contract">
  <h1>{{title}}</h1>
  <p>委託者（甲）: {{#corporation}}{{clientCompany}} / {{/corporation}}{{clientName}}</p>
  <p>受託者（乙）: {{issuer.companyName}}</p>
  <ul>{{#each scope}}<li>{{this}}</li>{{/each}}</ul>
  <div class="esign-issuer-seal">{{issuer.seal}}</div>
</div>
```

- `schema.json` にない名前（綴りの違いを含みます）の `{{…}}` は、空欄になります。新しいひな形は、自分宛てに一通作って管理画面で本文を確かめ、署名前に無効にしておくと、仕上がりを確かめられます。
- `list` の項目は、`{{#each}}` の中で使います。
- `{{#each}}` や `{{#corporation}}` の閉じ忘れなどで `{{` が残ると、作成のときにエラーになります。
- 見た目は、`app/globals.css` の `esign-contract`（全体）・`esign-signatures`（署名欄を 2 列に）・`esign-issuer-seal`（印影の置き場）・`esign-warning`（注意書き）で整えられます。
- ひな形の HTML は、そのまま契約書のページに表示されます。編集はリポジトリを管理する人が行い、外から受け取った HTML は中身を確かめてから使います。
- ひな形はデプロイに含まれます。足したり直したりしたら、commit してデプロイし直すと作成画面に反映されます。
- 作成済みの契約書は、作成したときの本文で固定されています。ひな形を直しても、過去の契約書の本文はそのまま残ります。

### メールの文面を変える

メールの本文は `templates/mail/` にあります。

| ファイル | 使う場面 |
| --- | --- |
| `sign-request.txt` | 相手への署名依頼 |
| `signed-client.txt` | 相手への締結記録 |
| `signed-issuer.txt` | 発行者（`issuer.contactEmail`）への締結の知らせ |

差し込みに使える名前は、`{{clientCompany}}`・`{{clientName}}`・`{{title}}`・`{{signUrl}}`・`{{docNumber}}`・`{{signedAt}}`・`{{issuerCompany}}`・`{{issuerRepresentative}}`・`{{issuerEmail}}`・`{{issuerPhone}}` です。件名は `lib/esign/mail.ts` で決めています。

## 安全のための設計

- 管理画面と管理用の API に入れるのは、`ADMIN_EMAILS` に書いた Google アカウントです。入口（`proxy.ts`）でログインと許可を確かめ、管理画面のページ（`app/admin/layout.tsx`）と各 API でも、あらためて確かめます。
- 保存・削除などの書き込み操作では、送り元が `SITE_URL` の画面であることも確かめます。
- データベースには、サーバーの中から、サーバー用のキーで接続します。どのテーブルも RLS を有効にし、許可はサーバー用のキー（`service_role`）に絞っています。Supabase のキーは、サーバーの環境変数にだけ置きます。
- 資料のファイルは非公開の置き場に保存し、開くときに 10 分間有効なリンクを作ります。
- 署名用リンクのトークンは 32 バイトの乱数です。データベースには、トークンの SHA-256 のハッシュを保存します。
- 署名は、「署名待ち」の契約書を「締結済み」に変える一回の更新で記録します。同じ契約書へ同時に二度送られても、記録されるのは先の一回で、あとの送信には「署名済みです」と返します。署名の画面でも、送信中のボタンを押し直せないようにしています。
- 署名の送信は、同じ IP アドレスから 1 分に 5 回までです。
- 署名ページは検索エンジンに載せない設定（noindex）で、フォームには自動送信を見分ける隠し項目があります。
- 画面には Content-Security-Policy、ほかのサイトへの埋め込みの禁止、HSTS などのヘッダーを付けています。
- CSV の書き出しでは、表計算ソフトが数式として扱う文字で始まる値の先頭に `'` を付けます。

## 知っておいてほしい制約

- **署名の連打の制限は、サーバーのメモリで数えます。** Vercel では複数のサーバーが並んで動くことがあり、そのぶん制限の効きは弱くなります。必要に応じて、Vercel の Firewall などで上限を足せます。
- **送り主の IP アドレスは、`x-forwarded-for` ヘッダーの先頭の値を使います。** Vercel では、このヘッダーを Vercel が付け直します。Vercel 以外の場所で動かす場合は、手前のプロキシがこのヘッダーを付け直す設定になっているかを確かめてください。付け直さない構成では、送り主がこの値を自由に書けるため、記録される IP アドレスと回数の制限が偽装されることがあります。
- **締結後の閲覧リンクは、初期値で期限がありません。** 署名用リンクは、締結後も契約書と締結記録を開くリンクとして使えます。期限を付けるには、`kit.config.ts` の `signedDocumentViewDays` に日数を入れます。
- **署名用リンクが出るのは、作成した直後の画面とメールです。** トークンはハッシュで保存しているため、あとから管理画面で表示し直すことはできません。リンクが手元にないときは、署名前なら無効にして作り直します。
- **契約書の本文は、作成したときに固定されます。** 内容を直すときは、署名前なら無効にして作り直します。締結済みの契約書は、記録として残り続けます（画面に無効化や削除の操作は出ません）。
- **ファイルの大きさ**: 画面では、資料を 20MB まで、CSV を 5MB・5,000 行まで受け付けます。Vercel の関数は、一回のリクエストの大きさの上限が 4.5MB のため、Vercel では、それより大きいファイルは途中で止まります（[Vercel の関数の制限](https://vercel.com/docs/functions/limitations)）。
- **件数の目安**: 連絡先の一覧・検索・CSV の書き出しは、全件を 1,000 件ずつ読んでから絞り込みます。数万件を超えると表示に時間がかかるようになります。契約書の一覧は、新しい順に 50 件を表示します（カルテには、その連絡先の契約書がすべて出ます）。
- **CSV は UTF-8 で読み込みます。** Excel で作るときは「CSV UTF-8」の形式で保存します。段階の列は `stageTags` にある名前を使います（空なら最初の段階）。タグは `|`・`;`・`、` で区切ります。メールが既存の連絡先や同じファイルの別の行と同じ行は、重複として取り込みから外します。
- **締結記録のメールが送れなかったときも、締結は記録されます。** メールの成否は画面に出ないため、届かないときは送信の設定（Resend の管理画面や SMTP のサーバー）を確かめます。署名依頼のメールが送れなかったときは、作成した契約書と署名用リンクが画面に出ます。
- **ログインと書き込み操作は、`SITE_URL` の URL で使います。** Vercel のプレビュー（ブランチごとの URL）での確かめは、ローカルで行います。

## 新しい版に更新する

[手順 8](#8-vercel-にデプロイする) で `upstream` を付けた場合は、自社のリポジトリのフォルダで次を実行します。

```bash
git fetch upstream
git merge upstream/main
npm ci
npm test
```

- `supabase/migrations/` に新しい番号のファイルが増えていたら、増えた分だけを番号順に適用してから、デプロイします。
- `kit.config.example.ts` や `.env.example` に項目が増えていたら、`kit.config.ts` と環境変数に足すかを確かめます。
- 自社のリポジトリへ push すると、Vercel がデプロイし直します。そのあと、自分宛てのテスト契約で一巡を確かめます。

Claude Code に任せる場合は、[PROMPT.md の「新しい版が出たとき」](PROMPT.md#新しい版が出たとき)の枠を貼り付けてください。
